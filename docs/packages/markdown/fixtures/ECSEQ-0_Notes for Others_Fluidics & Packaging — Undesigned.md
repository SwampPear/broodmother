# Fluidics & Packaging — No Physical Design Yet

**2026-07-22** · found while walking through the hardware architecture with Jack. Not legal advice.

**Severity: 🟡 — not physics-blocking for single-pixel go/no-go, but blocking for anything past it.**

## What

Nowhere in [[Whitepaper]], the patent draft/[[Provisional Patent Application No. 1 — Filing Copy|filing copy]], or [[Peripheral Device]] is there an inlet, outlet, chamber, reservoir, pump, tubing, or packaging spec. Fluid handling is described only **functionally**, never physically:

- library "flowed over the functionalized array"
- sequencing buffer "is introduced"
- surface regenerated by a "denaturing strip" between runs

None of these say how the fluid actually gets there, what holds it, or how it's exchanged.

## What IS decided, constraining the design

**No per-cycle wash** — a structural advantage over every cyclic competitor. Whatever the physical fluid path turns out to be, it only needs to support occasional bulk exchanges (run-start load, an optional mid-run top-up, the between-run strip/reload) — not the hundreds of precise per-base exchanges a platform like Illumina needs.

[[Whitepaper]] already flags one open sub-question directly: whether the reagent pool needs **periodic bulk replenishment** over a run, or can run PacBio-style from a **single loaded volume** for the whole run — called out explicitly as *"an open engineering parameter rather than a settled design choice."*

## Impact

- **Prototype (now):** the 4-pixel die needs *something* holding electrolyte over it. Almost certainly a simple bench droplet or open cell is sufficient for single-pixel validation — but that's an inference from "direct-wired, no mux," not written down anywhere.
- **Past the prototype:** any real packaging/instrument design has zero fluidics spec to build from yet.

## Do this

**Owner: Engineering (instrument/packaging) — currently unowned.** Scope a minimal fluidics spec, even at prototype scale: chamber vs. open-cell approach, reservoir volume, exchange method for the between-run strip. Resolve the bulk-replenishment-vs-single-load question before single-pixel validation needs repeatable buffer handling, so it isn't still open once that becomes a bottleneck.
