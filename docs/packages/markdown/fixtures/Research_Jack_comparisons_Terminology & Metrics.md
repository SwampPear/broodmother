# Terminology & Metrics

Status: reference glossary for the [[Competitors]] analysis. Written 2026-07-17. Defines every metric used to compare sequencing platforms in this folder, and — critically — which of those metrics are directly comparable across technologies and which are not.

This note has no company-specific numbers. See individual company folders for platform profiles and instrument-level data, and `Instrument & Market Comparison.md` for the cross-company tables.

## 1. Throughput and yield

- **Throughput** — the general term for how much sequence data a system produces per unit time (per run, per day, per year). Ambiguous on its own; always paired with a unit (Gb/run, Gb/day, reads/hour).
- **Reads per run** — the count of individual sequenced fragments (reads) a run produces. A "read" is one continuous basecalled stretch from one sequencing event (one cluster, one well, one pore channel, one ZMW, one nanoball, one bead), not necessarily one whole input DNA molecule — a single long input molecule sequenced with paired-end short-read chemistry produces two reads (see below); a single long input molecule sequenced on a long-read platform typically produces one read.
- **Bases per read / read length** — the number of called bases in a single read. Reported as a mean or median, since real runs produce a **read-length distribution**, not a fixed number.
- **Read-length distribution** — the histogram of read lengths in a run. Short-read platforms (Illumina, MGI, Element, Ultima) produce a narrow, fixed-length distribution set by the sequencing chemistry's cycle count (e.g., 2×150 bp). Long-read single-molecule platforms (ONT, PacBio) produce a wide, right-skewed distribution set by the input DNA fragment-length distribution, since (with the partial exception of PacBio's circular consensus, below) each read reflects one physical input molecule.
- **N50 read length** — the length L such that 50% of total sequenced bases are contained in reads of length ≥ L. N50 is a *yield-weighted median*, not a simple average — it is pulled upward by long reads far more than a mean would be, which is why long-read companies report it prominently. N50 is only a meaningful headline number for platforms with a broad read-length distribution (long-read); for short-read platforms with a fixed cycle length, N50 ≈ the fixed read length and is not informative.
- **Paired-end sequencing** — reading a fragment from both ends (Read 1 and Read 2), producing two reads per input fragment separated by an unsequenced "insert" gap. Standard on short-read platforms (Illumina, MGI, Element, Ultima) to improve alignment confidence, enable insert-size-based structural-variant detection, and effectively double usable sequence per cluster/well. Long-read single-molecule platforms do not need paired-end reads because one read already spans the whole fragment (or, for PacBio HiFi, multiple passes over the same fragment — see consensus accuracy below).
- **Yield per run** — total bases produced in a run = reads per run × mean read length (roughly; exact figure is the sum over the real distribution). Usually reported in Gb (gigabases, 10⁹ bases) per run; very large short-read runs are reported in Tb (terabases, 10¹² bases).
- **Gigabases (Gb) and terabases (Tb)** — 1 Gb = 10⁹ bases; 1 Tb = 1,000 Gb = 10¹² bases. A 30× human genome (see below) is ~90–100 Gb.
- **Run time** — wall-clock time from start of the sequencing run (first cycle/first signal acquisition) to completion of the last cycle, excluding library prep and analysis. Ranges from ~1 hour (ONT, adaptive/rapid runs) to several days (high-output short-read runs, some long-read runs chasing maximum yield).
- **Sample-to-answer time** — the far more clinically relevant number: time from raw sample (e.g., blood draw, extracted DNA) to a reported/actionable result, including extraction, library prep, run time, and analysis/basecalling/variant calling. This is what determines clinical utility for time-sensitive use cases (e.g., ICU rare-disease diagnosis, outbreak genomic surveillance) and is where instrument-level run-time comparisons can be misleading if prep and analysis time aren't included.

## 2. Accuracy

- **Raw-read accuracy** — the per-base accuracy of a single, individual read before any consensus or correction step. This is the metric most affected by the underlying physical/chemical error mode of a platform (see each company's Application Specialization section): fluorescence dephasing/phasing errors for SBS platforms, homopolymer miscalls for Ion Torrent and (to a lesser degree with newer chemistry) nanopore, and stochastic current-noise miscalls for nanopore.
- **Consensus accuracy** — the accuracy obtained after combining multiple independent observations of the same underlying template: multiple raw passes over the same circularized molecule (PacBio CCS/HiFi), duplex reads of both strands of the same original duplex molecule (ONT Duplex), or multiple reads from the same PCR-clonal population (any amplification-based platform's depth-of-coverage consensus in variant calling). Consensus accuracy is always higher than raw-read accuracy for the same platform, often dramatically so (PacBio raw single-pass ~87–92% → HiFi consensus ~99.9%). Comparing one platform's *consensus* accuracy to another's *raw-read* accuracy is a common and misleading error in vendor marketing; this analysis always specifies which is being reported.
- **Q scores (Phred quality scores)** — a logarithmic encoding of the estimated probability that a given base call is wrong: Q = −10·log₁₀(P_error). Q20 = 1% error probability (99% accuracy), Q30 = 0.1% error (99.9% accuracy), Q40 = 0.01% error (99.99% accuracy), Q50 = 0.001% error (99.999% accuracy). Q scores are estimated per-base by the basecaller from signal characteristics, and their *calibration* (whether a claimed Q30 base is really wrong 1 time in 1,000) varies by platform and basecaller version — a Q score is only as trustworthy as the basecaller producing it, which is itself a moving target as ONT and PacBio periodically release improved basecaller models applied retroactively to raw signal.
- **Substitution vs. insertion/deletion (indel) errors** — the two broad error classes, and their ratio is a defining, physically-grounded characteristic of each platform (detailed per-company). SBS and SBB platforms are substitution-dominated (a wrong base is called, but the read stays in register). Homopolymer-sensitive platforms (Ion Torrent unmodified nucleotide flows; nanopore, to a lesser degree with current chemistry) are indel-dominated, because the physical signal from a run of N identical bases is a magnitude/duration measurement that becomes harder to resolve into an exact integer N as N grows, and an off-by-one miscall shifts the reading frame.

## 3. Coverage and cost

- **Depth of coverage ("coverage", "Nx")** — the average number of independent reads overlapping a given genomic position = (total yield in bases) / (genome size in bases). 30× is the conventional depth for clinical-grade human whole-genome sequencing (enough to call heterozygous variants reliably against Illumina/short-read-era error rates); higher depth (40–60×+) is used for some long-read or lower-per-read-accuracy platforms to reach equivalent variant-calling confidence via consensus.
- **Cost per gigabase (cost/Gb)** — list reagent/consumable cost of a run ÷ yield in Gb. The single most-used cross-platform cost metric, but it hides read-length- and application-dependent value: a Gb of long reads is worth more for structural-variant/assembly work than a Gb of short reads, and a Gb of high-accuracy reads is worth more than a Gb of low-accuracy reads for variant calling at a given depth.
- **Cost per million reads** — relevant for applications where read *count* matters more than base yield (e.g., single-cell RNA-seq, some targeted panels, low-pass sequencing), since library complexity and PCR duplicate saturation are governed by read count, not Gb.
- **Cost per sample** — total consumable/reagent cost of a run ÷ number of samples multiplexed onto that run. Depends on both cost/Gb and how deeply each sample needs to be sequenced for its application (e.g., a shallow non-invasive prenatal test needs far less depth/cost per sample than a clinical WGS).
- **Cost per genome** — cost per sample specifically at the ~30× human WGS depth convention; the headline figure vendors compete on ("the $200 genome," etc.). Only comparable between platforms when the accuracy/depth basis is stated, since a platform claiming a lower cost per genome at higher error rates, or via lower-confidence consensus depth, is not offering an equivalent product.
- **Instrument utilization** — the fraction of an instrument's theoretical maximum annual run-time that is actually used for revenue/production runs, after accounting for maintenance, failed runs, queueing, and non-continuous operation (nights/weekends in many labs). Realistic utilization in a well-run production sequencing core is commonly modeled at 70–85%; this analysis states its assumed utilization figure explicitly wherever it appears in a "realistic annual output" calculation, and labels the result "calculated from reported data."
- **Sequencing capacity per day / month / year** — nameplate throughput (Gb/run ÷ run time, scaled up) multiplied out to a time period. Distinguish **theoretical maximum** (100% utilization, back-to-back runs, no failures) from **realistic/practical** (utilization-adjusted) capacity — both are reported per platform in this analysis, explicitly labeled.

## 4. Scaling

- **Horizontal scaling** — increasing total sequencing capacity by increasing the number of simultaneous, physically parallel sequencing sites (or instruments): more pores, wells, clusters, beads, nanoballs, imaging sites, chips, flow cells, or whole instruments. A horizontally-scaled system's output grows roughly linearly with the number of sites/instruments added, at constant per-site performance.
- **Vertical scaling** — increasing the output of each *individual* site or instrument: faster template translocation/incorporation cycles, shorter imaging/signal-acquisition time, better fluidics exchange, longer-lived pores/reagent chemistry, longer reads per site, better duty cycle (fraction of time a site is actively producing usable signal vs. idle/washing/imaging), higher sensor sampling rate, better signal-to-noise ratio, improved chemistry, improved basecalling (extracting more usable bases from the same raw signal), or denser site packing per unit area.
- **Pore / well / cluster / nanoball / bead / sensor-channel counts** — the platform-specific unit of "one physically independent site capable of producing one read stream." These counts are *not* directly comparable across technologies without normalizing for what fraction are active, loaded, and produce a passing read (below), and without normalizing for bases produced per site (a nanopore channel run for 72 hours produces vastly more bases per site than an Illumina cluster imaged for 300 cycles).
- **Active-channel / active-site percentage** — the fraction of total physical sites on a device that are electrically/optically functional and available to be used in a given run (as opposed to manufacturing defects or already-exhausted, e.g. a decayed nanopore).
- **Loading efficiency** — the fraction of active sites that actually receive a usable template molecule (not empty, not multiply-loaded/polyclonal) during library loading. Governed by library concentration, molecule length/diffusion behavior, and site geometry; a major practical lever operators tune per run.
- **Occupancy** — closely related to loading efficiency; specifically the fraction of active sites occupied by a template at a given point in the run (nanopore terminology: pore occupancy, which decays over a run as templates are consumed or pores fail).
- **Usable-read percentage (pass rate)** — the fraction of reads that clear a platform's basecalling/quality filter and are retained in the reported yield (e.g., ONT's "pass" vs. "fail" reads by mean Q score threshold; Illumina/MGI's filtering of polyclonal, low-quality, or adapter-only clusters).
- **Consumables pull-through** — the recurring reagent/flow-cell/chip revenue per instrument over its life, the basis of the vendor "razor/razorblade" business model; a proxy for real-world utilization and switching cost, distinct from list run cost.

## 5. What is, and is not, directly comparable across technologies

**Directly comparable, with care:**
- Cost/Gb, cost/genome, cost/sample — comparable in dollar terms, but only meaningful alongside the accuracy/depth basis, since a cheaper Gb of noisier or shorter data is not an equivalent product.
- Run time and sample-to-answer time — comparable in wall-clock terms, always.
- Yield/run, Gb/day, Gb/year — comparable in raw-output terms, but say nothing about read length, accuracy, or application fit.
- Q scores — comparable in principle (all express the same error-probability logarithm) but only as trustworthy as each platform's basecaller calibration, which is not independently audited on a common standard in most vendor literature; independent benchmark papers (e.g., Genome in a Bottle consortium studies) are the more reliable source than vendor-reported Q scores.

**Not directly comparable without normalization, or not comparable at all:**
- Raw physical site counts (pores vs. wells vs. clusters vs. beads vs. nanoballs) — different technologies extract wildly different amounts of sequence per site over wildly different timescales; a raw count comparison is close to meaningless without normalizing to bases/site/run and run duration.
- Read length headline numbers across short- vs. long-read platforms — a short-read platform's "300 bp" and a long-read platform's "N50 20 kb" answer different questions (fixed cycle length vs. yield-weighted median of a broad distribution) and serve different applications; neither is "better" in the abstract.
- Raw-read accuracy compared against another platform's consensus accuracy — see above; this is the single most common apples-to-oranges error in cross-platform marketing claims, and this analysis calls it out wherever it appears.
- List instrument price alone, without amortization over expected throughput and lifetime — a cheaper benchtop instrument with expensive per-run consumables can have a higher effective cost/Gb than an expensive high-throughput instrument at scale; total cost of ownership (instrument capital + consumables + labor + facility, amortized over a realistic annual output) is the only fair comparison for a purchasing decision, and is addressed separately in `Instrument & Market Comparison.md`.
